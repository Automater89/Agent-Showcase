# RAID Log: Employee Offboarding Process Redesign

**Project:** Employee Offboarding Process Redesign  
**Organization:** [Automotive Manufacturing Company]  
**Prepared by:** AI Process Innovation Analyst  
**Date:** May 2026  
**Review Cadence:** Bi-weekly during active project phases  

---

## RAID Log Table

| Category | Item | Description | Owner | Mitigation or Note | Status |
|---|---|---|---|---|---|
| **Risk** | HRIS Integration Complexity | The current HRIS (SAP HCM or Workday) may have limited API availability or require costly configuration to support automated task triggering and data extraction for the new offboarding workflow. | IT Architecture Lead | Conduct integration discovery sprint in Phase 1; evaluate Power Automate connectors and middleware options (e.g., Azure Logic Apps) before committing to design. | 🟡 Open |
| **Risk** | Union Contract Compliance | Changes to offboarding steps affecting hourly, union-represented employees may require review and approval through collective bargaining channels, potentially delaying implementation for that workforce segment. | HR / Labor Relations | Engage Labor Relations in Phase 1 to map which process steps are governed by the CBA; design union-compatible workflow variants as needed. | 🟡 Open |
| **Risk** | Low Manager Adoption of Digital Intake Form | Managers accustomed to informal email notification may resist or bypass the new structured intake form, undermining the automated downstream trigger model. | HR Change Management Lead | Include managers in co-design workshops; build the form into existing tools (Teams, Outlook) to minimize friction; track bypass rate as a KPI post-launch. | 🟡 Open |
| **Risk** | Physical Access Control System Not API-Accessible | The facility's badge and physical access system may not support API integration with Power Automate, requiring manual Security team steps to remain in the To-Be process. | IT / Security Admin | Assess API or webhook capability of current access control system in Phase 1; if not available, design a structured manual trigger with SLA enforcement as interim solution. | 🟡 Open |
| **Risk** | Employee Data Privacy and AI Use Disclosure | Using AI to classify exit interview responses may trigger employee privacy concerns or legal review requirements, particularly in jurisdictions with strict data protection regulations. | Legal / Compliance | Consult Legal in Phase 1 to confirm AI use disclosure requirements; include clear employee consent language in exit interview communications; ensure data is anonymized before classification. | 🟡 Open |
| **Assumption** | Microsoft 365 Is the Standard Productivity Platform | The redesign assumes the organization uses Microsoft 365 (Teams, Outlook, SharePoint, Power Automate, Copilot) as its primary productivity and automation platform, enabling native integration without additional tooling procurement. | IT / Project Sponsor | Confirm licensing tier (Power Automate premium connectors, Copilot licensing) is in place or budgeted before design is finalized. | 🟢 Confirmed |
| **Assumption** | HRIS Contains Accurate, Current Role and Employment Data | The automated knowledge transfer checklist and final pay assembly depend on accurate role classification, pay rate, PTO balance, and department data in the HRIS. | HR Data / HRIS Admin | Conduct a data quality audit of HRIS records for active employees as part of Phase 1; identify and remediate gaps before automation is built on top of the data layer. | 🟡 Pending Verification |
| **Assumption** | Departing Employees Will Complete Digital Exit Surveys | The AI-driven exit interview analysis model depends on employees actually submitting the digital survey. Current completion rates are unknown but assumed to be improvable with better timing and UX. | HR Coordinator | Set a baseline completion rate target (e.g., ≥70%); test survey timing (send 5 days before last day vs. day of); consider brief pulse format over long-form to improve response rates. | 🟡 Pending Baseline |
| **Assumption** | Stakeholders Will Participate in Co-Design Workshops | The process redesign assumes meaningful participation from Manager, HR, IT, Payroll, Security, and Legal representatives in discovery and validation workshops during Phase 1. | Project Manager | Secure stakeholder commitments and time allocations before Phase 1 kickoff; identify backup representatives for each function in case of scheduling conflicts. | 🟢 Confirmed |
| **Issue** | No Single Owner for Offboarding Process Currently Exists | There is no designated process owner for offboarding across the organization. Accountability is distributed informally, making it difficult to drive change, enforce standards, or hold teams accountable to SLAs. | HR Leadership | HR Leadership must designate an Offboarding Process Owner before the To-Be design is finalized; this role will own the workflow, KPIs, and continuous improvement post-launch. | 🔴 Blocking |
| **Issue** | Exit Interview Data Is Stored in Multiple Unconnected Locations | HR teams across facilities store exit interview responses in personal drives, local spreadsheets, and email inboxes — making it impossible to build an AI classification model on top of existing data without a data consolidation effort first. | HR Coordinator / Data Lead | Conduct a data consolidation sprint to centralize historical exit interview data into a single SharePoint list or data lake before AI classification tooling is deployed. | 🔴 In Progress |
| **Issue** | IT Deprovisioning SLAs Are Undefined | There are currently no documented SLAs for how quickly IT must revoke access after an offboarding notification is received. Without a baseline, it is impossible to enforce improvement or measure To-Be performance. | IT Admin / HR | Define and formally agree on deprovisioning SLAs (e.g., standard access revoked within 4 hours of last day; privileged access revoked same-day) as part of Phase 1 requirements. | 🟡 Open |
| **Issue** | Knowledge Transfer Has No Documented Standard | There is no existing template, framework, or minimum standard for what constitutes a complete knowledge transfer at this organization, making it impossible to automate or enforce without first defining what "done" looks like. | HR / Operations Manager | Develop a Knowledge Transfer Standard (minimum required documentation by role family) in Phase 1; use this as the basis for the auto-generated checklist in the To-Be process. | 🟡 Open |
| **Dependency** | HRIS API / Integration Readiness | The automated offboarding trigger, task routing, and final pay data assembly all depend on the HRIS exposing reliable APIs or being connectable via Power Automate. This must be confirmed before workflow design is finalized. | IT Architecture Lead | Integration discovery is a Phase 1 gate; if native connectors are unavailable, an integration middleware solution must be scoped and budgeted before Phase 2 begins. | 🟡 In Discovery |
| **Dependency** | Physical Access Control System API or Webhook Support | Badge deactivation automation depends on the facility's access control system supporting programmatic integration. If it does not, the Security swimlane must be redesigned with a structured manual process. | IT / Security Admin | Assess by end of Phase 1; results will determine whether Security automation is included in the Phase 2 build or deferred to a later release. | 🟡 In Discovery |
| **Dependency** | Copilot / Azure AI Licensing and Governance Approval | The AI classification of exit interview data and the Copilot-generated summary features require Microsoft Copilot licensing and internal AI governance approval before they can be deployed in production. | IT / Legal / AI Governance | Submit AI use case for governance review in parallel with Phase 1; do not build AI features until approval is confirmed. | 🟡 Pending |
| **Dependency** | Manager and HR Coordinator Training Completion Before Go-Live | The success of the To-Be process depends on managers and HR Coordinators understanding and adopting the new intake form, dashboard, and checklist tools before launch. | HR Change Management Lead | Build training and change management plan in Phase 2; schedule mandatory training sessions no later than 2 weeks before go-live; include simulation exercises with the new tools. | ⬜ Not Started |
